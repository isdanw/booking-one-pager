# 一页预约（booking-one-pager）

## 一、怎么打开、点哪里、第一步做什么

1. **打开**：双击 `index.html`（Chrome / Edge / Safari 都行）。不需要安装、不需要联网、不需要账号。
2. **第一步**：页面默认停在「**经营者**」视图，看第 1 张卡片「**设营业时间，自动拆时段**」：
   - 填 **服务名**（例：剪发（男士））；
   - 选 **单个服务时长**（例：30 分钟）；
   - 选 **营业日期**、**连续几天**（例：明天，1 天）；
   - 填 **营业开始 / 结束**（例：09:00–18:00）；
   - 点「**按营业时间拆分**」。
3. **第二步**：下面立刻出现「拆出来的时段」—— 09:00–09:30、09:30–10:00…… 每天一组。时间框可以直接改，不要的按「删除」，缺的按「+ 补一段」（会优先补空档）。确认无误点「**保存并挂出去**」。
4. **第三步**：点右上角切到「**客户**」视图 —— 这就是客户看到的样子：一整天的时间轴，每段标「空闲」或「已约满」。
5. **第四步**：点一个「空闲」段 → 填姓名、手机号 → 「确认预约」。该段**立刻**变成「已约满」，不可再点。
6. **第五步**：切回「经营者」，第 3 张卡片「**预约单**」就是所有单子；点「**导出 CSV**」/「**导出文本**」/「**复制文本**」把单子拿走（CSV 带 BOM，Excel 直接打开不乱码）。

> 想先看效果：第 1 张卡片右上角「**填入示例数据**」，会写入纯虚构的样例（服务「剪发（男士）」09:00–12:00 拆成 6 段，其中 09:30 那段已被「张三 / 13800000000」约满）。

## 二、痛点

个体经营者（理发、美甲、按摩、修锁、宠物洗护、家教、小工作室……）反复抱怨的其实是三件事：

1. **预约工具是给大公司做的** —— 员工排班、会员储值、多门店、报表，全用不上。
2. **配置要两周** —— 注册、绑定、装修页面、配规则、等审核，黄花菜都凉了。
3. **我只想当天挂出去、有人约、能看到单子** —— 中间所有环节都是成本。

这个工具就是那条最短路径：**填一个营业时间，系统自己把一天拆成时段；客户点一下；你在一个表格里看单。**

## 三、这一版做了什么（v2）

- **营业时间 → 自动拆分**：给「营业开始 / 结束 + 单个服务时长」，按时长等分生成连续时段；末尾不足一个完整时长的零头直接跳过，并在按钮旁提示（例：`每天 18 段 × 2 天，共 36 段（末尾 30 分钟不足一段，会跳过）`）。
- **逐段可改**：每段两个时间框直接改。改完立刻校验「结束要晚于开始」「不能和别的段重叠」，不合法会**自动回滚**并提示原因。
- **逐段可增删**：单段「删除」；「+ 补一段」会先找当天的空档补进去，实在没有才往末尾接；整天可以一键删掉。
- **客户页是整天时间轴**：左侧竖线 + 圆点，每段一行显示「09:00 – 09:30 · 30 分钟 · 空闲 / 已约满」，已约满的置灰不可点，圆点变红。
- **提交即锁定**：预约成功后该段立刻变「已约满」；同一段第二次预约会被挡下（详见验收 ⑥）。
- **数据全在本地**：`localStorage` + 导出 TXT / CSV，不上传、不接任何外部服务。
- 保留 v1 能力：建服务、防重复、列表与导出逐字段一致、手机宽度无横向溢出。

## 四、验收步骤

| 验收项 | 操作 |
| --- | --- |
| ① 自动拆分 | 服务名随便填 → 时长 30 分钟 → 日期选明天 → 营业 09:00–18:00 → 点「按营业时间拆分」→ 出现 18 段，按钮旁显示「每天 18 段」 |
| ② 单段调整 | 把第 1 段结束时间从 09:30 改成 09:45 → 弹出「和 09:30–10:00 这段重叠了」，输入框自动退回 09:30；把最后一段改成 18:30 → 生效，时长标签变「60 分钟」 |
| ③ 单段增删 | 删掉第 1 段（18→17）→ 点「+ 补一段」→ 又回到 18 段，补回的正是 09:00–09:30 |
| ④ 时间轴 | 保存后切「客户」：每天一条时间轴，每段一行，右侧标「空闲」或「已约满」 |
| ⑤ 预约即锁定 | 点任意「空闲」段 → 填 张三 / 13800000000 → 确认 → 该行立刻变红显示「已约满」，点不动 |
| ⑥ 第二次被挡 | 已约满的段点了没反应；就算绕过界面（另一个标签页抢先下单），确认时也会提示「这个时段已约满（刚被别人约走），换一段吧」，不会写入第二条 |
| ⑦ 列表=导出 | 「预约单」表格与「导出 CSV / 导出文本」逐行逐字段一致（同一份数据、同一个排序） |
| ⑧ 手机不溢出 | 窗口拖到手机宽度（或手机打开），页面无横向滚动条；只有预约单表格在卡片内部横向滚动 |

## 五、实现要点

- **单文件**：HTML + CSS + JS 全内联，零依赖、零构建、零网络请求（不加载任何 CDN / 字体 / 统计）。
- **数据**：`localStorage` 键 `booking_onepager_v1`，结构 `{ services: [{id, name, duration, openStart, openEnd, slots:[{id,date,start,end}]}], bookings: [...] }`。
- **拆段**：时间统一换算成「分钟数」再做整数步进，避免时区问题；`09:00–18:00 ÷ 30 分钟 = 18 段`。
- **防重复**：提交前重新从 `localStorage` 读最新数据再判一次（不是只看内存），所以同一时段第二次一定被挡；提示语明确，弹窗保持打开让人换一段。
- **导出**：CSV 与 TXT 都由同一个 `sortedBookings()` 生成，和页面表格同源。
- **降级**：浏览器禁用本地存储（某些隐私模式）时，页面底部出现红字提示，工具仍可在本次打开期间使用。

## 六、局限（明确不做）

- **不接日历同步**：不往系统日历 / Google 日历写事件，也不读你的日历。
- **不接支付**：没有定金、没有在线收款，收钱还是线下。
- **不做多门店 / 多员工**：一个页面 = 一个经营者，没有员工排班与权限。
- **不是真正的并发系统**：没有服务端。「防重复」是单机 `localStorage` 层面的判重 —— **同一个浏览器**里绝不会重复；但客户在自己电脑上打开同一份文件时，两边数据互不相通。设计前提是「把你的电脑/平板放在店里给客户点」，或你代为录入。
- **数据不跨设备**：换浏览器、换电脑、清网站数据就没了，重要单子请先导出。
- **没有身份验证**：「经营者」和「客户」只是同一页面上的两个视图，谁打开都能切。
- **没有通知**：客户约完不会收到短信/微信提醒，得自己看预约单。
- **休息时间要手动处理**：拆段是「从营业开始连续切到营业结束」，午休之类请把中间那几段删掉，或者上午/下午各建一个服务。
